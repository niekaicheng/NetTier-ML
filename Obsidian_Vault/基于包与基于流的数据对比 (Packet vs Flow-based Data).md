# 基于包与基于流的数据对比 (Packet vs Flow-based Data)

在网络入侵检测和网络数据分析中（参阅 [[A Survey of NIDS Data Sets (Ring et al. 2019)]]），采集上来的最基础形态分出两个岔路口。它是一切监督/无监督提取器训练的输入锚点分类。

## 1. 基于包（Packet-based data）
以 `.pcap`（Packet Capture）为代表的全量捕获格式。
- **特点**：不仅包含了网络报文的首部（Source ID, TCP Flags, 序列等），而且包含了**完整的载荷（Payload）**的实际数据。
- **优势**：上帝视角，对于不需要加密或者破解了加密的隧道，基于签名的规则匹配可以说是百分百精度的拦截（DPI）。
- **劣势**：在大厂带宽中极其吃存储和算力，并且一旦面对 [[加密流量分类 (Encrypted Traffic Classification)]]，Payload 会变成乱码而几乎丧失意义；同时含有极大的隐私合规风险。

## 2. 基于流（Flow-based data）
将拥有相同网络行为（如默认的五元组：源 IP、源端口、目的 IP、目的端口、传输协议）的封包在这个时间窗内的总体情况聚合出一条记录。代表格式是 `NetFlow` 或 `IPFIX`。
- **特点**：完全踢掉 Payload 载荷，只保留网络宏观元数据（如这条流花了多久、几个包组成、总字节多少、第一个包是啥 TCP flag）。
- **优势**：极度轻量级！存储空间被十倍百倍地压缩，天生脱敏不用太顾忌隐私。
- **学术引用比喻**：“如果说查 Packet 是让你在一片森林里跋涉并且翻看每一片落叶，那么查 Flow 就是让你坐在这个森林上空的热气球俯瞰林相（Wheelus et al., 2014）”。

## 深度学习的兼容选型
早年的传统 ML / 浅层学习 往往喜欢使用加工过的 Flow 数据；而如今像 CNN 甚至是 Transformer 大规模上阵后（例如提取 28x28 的报文首部截断图像化），大都必须以 Packet-based data 做基础去截取首部的十六进制片段自行计算空间相关性。
